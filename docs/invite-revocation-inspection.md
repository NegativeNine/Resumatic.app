# Inspecting quarantined invitation accounts

Use `GET /admin/invites/revocations/:operation/accounts` to inspect the Directory's point-in-time account observations for a pending invitation revocation. This endpoint requires the same Cloudflare Access authorization as other admin routes. The operation is the UUID used as the revocation's idempotency key. Responses contain owner and vault IDs, their Directory states, placement and the current Directory initialization-marker presence; they omit identities, email addresses, invitation tokens and career data.

The optional `limit` is 1–25 (default 25). Use `nextCursor` as `after` to request the next page. Each page is checked separately; the pages do not constitute one atomic snapshot. Repeat an inspection if the operation changes. An unavailable response means the tuple or its observation could not be verified; retain the quarantine and investigate. An operation with unresolved claim processing or legacy inventory returns `inventoryPending: true` and no account details.

`scope: "directory_observation_only"` is intentional. An absent marker or an `active` Directory state does not prove the Vault has finished initializing, that no earlier RPC remains in flight, or that a Vault belongs to a particular person. A response cannot authorize erasure, adoption, invitation reinstatement, fence removal or other reconciliation. Revoking an invite is not the account owner's consent to deletion. Continue to retain the quarantine and tombstones until a separately reviewed, owner-authorized protocol can prove the required ownership and quiescence guarantees.
