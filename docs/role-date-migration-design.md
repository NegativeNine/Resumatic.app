# Start dates when the end is unknown

A staged implementation stores an unknown-ended start separately as `unknownEndStartDate`, while the legacy `startDate` and `endDate` fields both remain null. Older readers therefore omit the start instead of printing an unsupported “Present.” The feature is off by default. Production preflight and release checks reject `ROLE_UNKNOWN_END_ENABLED=true` until rollout safety is established.

The explicit v2 role routes and Vault RPCs reject unsupported writes rather than silently dropping a field on an older version. The web form exposes the option only when both Worker and Vault advertise support. Legacy updates that leave both old date fields null preserve the unknown start; a non-null legacy date supersedes it. SQLite migration adds a separate column and a trigger for those legacy writes. New resume and share snapshots carry the field; old snapshots without it retain their historical interpretation. PDF and DOCX versions containing it use distinct cache keys, while old versions keep their original keys. Older renderers may omit the date during rollback; the separate key prevents their output from poisoning a newer rendering.

Extraction retains a start with an unknown end only when the source explicitly labels that start, such as a LinkedIn `Started On` cell. A standalone year, seasonal date, ambiguous range or unsupported end is not assumed to be a start. Manual v2 entries remain user-authored claims. This preserves some start-only dates but does not eliminate all seasonal-date recall loss.

The checked-in evaluation configuration hashes this behavior, scores the explicit unknown-end representation, and checks staging/production agreement. Staging deployment and CI live-evaluation jobs refuse to proceed if Worker secret names cannot be listed or shadow evaluated settings. Direct evaluation and manual deployment require the operator's same secret-name review described in the operations runbook.

Before enabling writes, verify mixed Worker/Vault and in-flight Workflow behavior, old browser/MCP clients, rollback, transfer and restore across schema versions, and real staging exports and extraction evaluations. An old Vault or Workflow may ignore the separate field and lose a proposed date even though its legacy date fields remain conservative. Do not enable production based solely on the flag or local tests; the release gate deliberately rejects it pending a reviewed rollout and drain procedure.
